# Exercise 2: Running Eva

We will now run our first Frama-C plug-in: Eva.

## Task 1: Running Eva

Parse and analyze file `2.c` with Eva.

The output of Eva is very verbose. For now, the most important lines are:

- Those with "Warning";
- The "ANALYSIS SUMMARY" at the end.

## Task 2: Running Eva in the graphical interface

Replace `frama-c` with `ivette` and run the analysis in the graphical interface.

Open the "Eva Summary" view (right-hand sidebar) and see a graphical summary of
the analysis coverage, as well as a panel (bottom-center) listing messages
such as warnings and alarms.

Now go to the "Properties" view and, using the Properties panel (bottom-center),
navigate to the point in the code where there is an alarm.

## Task 3: Understanding the alarms emitted by Eva

The alarm displayed in the AST panel (top-left) is written using an ACSL
annotation. It should be fairly self-explanatory.

## Task 4: Understanding "unreachable code"

In the Source Code panel (top-right), click in the `main` function. The AST
panel will navigate to it.

Two small vertical bars are displayed next to `int r = random();` and
`return r;`. Hover the mouse and read their meaning.

Knowing that Eva assumes that *undefined behaviors do not happen*, and
considering the previous alarm, how do you explain the fact that the function
call is "non-terminating"?

## Task 5: Fixing the code

Propose a simple fix to the code. Note that the graphical Frama-C interface
does *not* allow editing the code. You can right-click the Source Code panel
and open it with an external editor.

Note: you may need to go to menu File -> Preferences... to change the
Editor command associated with this menu (e.g. replace `emacs +%n:%c %s` with
`code %s`, or `vi %s`, or `gedit %s`, etc). Or you can quit Ivette and open
the source code manually.

Rename the modified file `2-fixed.c` and then re-run ivette with Eva.

Hint: There are multiple ways to fix the issue, you can choose any of them.
Remember that local and global variables are initialized differently in C;
also, C storage modifiers such as `volatile` and `extern` can change the
behavior w.r.t. initialization.

Check that your fix works: the Eva Summary panel should display 100% coverage
and 0 errors and alarms.
