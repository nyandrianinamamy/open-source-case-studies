# Exercise 5: Strings and stdlib

In this exercice, we will use some functions from the C standard library to
manipulate character buffers.

## Task 1: A simple program

Open `5.c` in your editor. This is a very simple program that reads user input,
copies it to a buffer, and prints it.

### Task 1.1: Breaking the program

Compile the program and run it. Try to find some input that will result in
undefined behavior.

*Hint 1*: This undefined behavior may not crash the program, and is not
highly visible. Consider checking the POSIX version of the `fgets` manpage
for hints about possible UBs.

Try and see if there are compiler options, sanitizers or tools such
as Valgrind that can alert about the issue.

After finding some input that triggers the UB, run a sanitized
program, as well as Valgrind, and see if they detect the issue.

*Hint 2*: With different compilation options, you can obtain different
results for the same code; this is often a sign of undefined behavior.
Note that some sanitizer options *require* enabled optimizations
(`-O2` or greater).

You can also run Frama-C on the file, but some alarms will not be immediately
obvious. They are explained later in the exercise.

### Task 1.2: Fixing the program

You will need to edit the code to fix it. Try to do so with minimal changes
(i.e. keep the call to `fgets`).

Then, after fixing it, try running the sanitized program and/or with Valgrind to
see if they report further issues.

## Task 2: Getting Frama-C/Eva to prove its correctness

*Disclaimer*: Eva is still lacking an ideal solution for handling strings, such
as a *typestate domain*. Until then, some workarounds and limitations are
expected when handling code that uses variable-length strings and standard
library functions manipulating them.

Open your fixed version of `5.c` with Ivette and Eva. You can use as much
precision as you want.

In the Properties view, you will have about 6 *Unknown* properties.
Some of them are duplicates, that is, when a function has a `requires` that is
Unknown, its instantiation at a specific call site (where the function is called)
will also be Unknown; but in practice both refer to the same condition.

One property in particular is cryptic: `valid_stream: \valid(stream)`.
Click on the `fgets` requires associated to it, and you will see Frama-C's
standard library specification for `fgets`. The `valid_stream` property is
meant to represent the fact that the `FILE` stream passed to the function must
be in a state where it can be read. This is the case for `stdin` when the
code reaches the `main` function, but such initialization is not yet properly
taken into account by Eva. For now, we can safely ignore it.

### Task 2.1: Using non-deterministic implementations

Some functions in the standard C library have non-deterministic implementations
in the libc provided by Frama-C. These implementations are simplistic versions
of the actual C library code, which is often platform-specific, compiler-specific,
and highly optimized. These aspects make such code very hard to analyze.
By providing its own implementations, Frama-C can help Eva maintain precision
when the ACSL specification is too complex or not precise enough.

To use such implementations, simply add the corresponding `.c` files to the list
of files to be parsed, e.g.:

    frama-c $(frama-c-config -print-share-path)/libc/stdio.c 5.c <options>`

Open both files in Ivette, with the proper Eva options, and observe that there
are fewer alarms than before.

### Task 2.2: Aggressive inlining

In order to remove all remaining alarms in this code, a more aggressive (and not
always practical) approach is to *inline functions*.

By default, Eva limits the combinatorial path explosion of its inteprocedural
analysis by merging analysis states at the end of each function. Some options
prevent it (`-eva-split-return`, `-eva-interprocedural-splits`), but the details
of how they work may require some complex setups. Therefore, for this exercise,
we will use a more syntatic approach: using Frama-C's `-inline-calls` option,
which can syntactically inline a function.

Use option `-inline-calls` on the `fgets` function, and run the analysis.
You should get 0 alarms.

## Task 3: Finally, some exploits!

Francis MacLaren, the best student of the Polytechnique University of
Paris-Saclay (PUPS), wanted to impress their teacher.
They* wrote a very simple program to store some student data (name and grade),
then added a lot of defensive programming to prevent careless (or malicious)
users from producing invalid data.

*For gender-fairness, we do not specify if Francis is male or female,
therefore we use the "they" pronoun.

In particular, Francis wants to make sure that the program:
1. Is free of runtime errors;
2. Will only allow valid grades (between 0 and 20).

Francis would also like to ensure that the name is valid, but "valid name"
is something no one in their school managed to agree on. Therefore, Francis
allows any non-empty string as a valid name.

Francis is convinced their program is bulletproof, and will not print the
last line unless everything is fine. However, Francis does not know how to use
Frama-C. You do.

### Task 3.1: Proving (or probing for weaknesses)

Read the program `5-2.c`, to get a vague idea of what it does. Then run
Frama-C/Eva on it and try to prove absence of undefined behaviors.

Note: by default, Frama-C is very strict with floating-point values, more than
the standard requires. Use option `-warn-special-float none` to disable spurious
warnings about floating-point values.

Using the previous techniques, you should either (1) be able to prove the
program has no UBs, or (2) find a counter-example in which some UB happens.

If you find a counter-example, run the program with it to make sure it produces
unexpected results.

### Task 3.2: Ensuring valid grades

The output of Francis' program will be used as input to a script, so it must be
free of errors concerning the grades.

As before, try to prove the program is fine, or find a counter-example.

Hint: Adding assertions at strategic places can help verify property 2.
It can also be used with Eva Values to inspect certain variables.

If you find a counter-example, run the program with it to make sure it produces
unexpected results.
